一、项目概述

EasyAI 是一款基于 Java 17 + Spring Boot 3.4 的智能客服框架，以 Spring Boot Starter 方式提供，能够快速集成到任意 Spring Boot 项目中。

它专注于企业客服自动化场景，通过 注解驱动配置 + 动态场景解析 + 智能参数收集 的方式，让开发者快速构建具备上下文理解能力的智能客服系统。

注解与字段属性映射关系

@AiTask（类级别）

  • type → 任务类型标识（如 ORDER_UPDATE）
  • name → 任务名称
  • action → 完成后执行的 Action 类
  • postActions → 后置动作列表（如 LOG）

@AiField（字段级别）

  • name → 字段中文名（追问时使用）
  • required → 是否必填
  • sensitive → 敏感字段（日志脱敏）
  • normalize → 归一化器类型

@AiExtract（提取配置）

  • description → LLM 提取提示描述
  • examples → 提取示例
  • rules → 提取规则约束

@AiValid / @AiMapping / @AiDependsOn

  • @AiValid → 校验器（可多个，管道执行）
  • @AiMapping → 值→动作参数映射（支持 $data）
  • @AiDependsOn → 前置字段依赖

八、设计亮点总结

1. 管道式架构（Pipeline）

将复杂的对话处理拆解为 9 个独立阶段，每个子引擎职责单一，可独立测试、独立替换。阶段间通过不可变的 TaskState 传递数据，降低耦合。

2. 配置版本绑定

任务创建时绑定特定 configVersion，整个生命周期使用同一版本配置。管理员发布新配置不会影响进行中的任务，避免 mid-task 行为突变。

3. 注解驱动 + 约定优于配置

通过 @AiTask 注解在 DTO 上声明任务配置，字段名/类型/顺序自动推导，开发者只需关注差异部分。启动时扫描转换为标准 Config 对象。

4. 可插拔 SPI 扩展

Validator、Action、Normalizer、LookupService、LLM 全部面向接口编程，业务方按需实现。框架内置通用实现（NotEmpty/Enum/Regex 等），复杂业务自行扩展。

5. 状态持久化与容错

每轮对话结束前持久化 TaskState，JVM 崩溃不丢失进度。异常被顶层捕获，状态标记为 FAILED 并返回友好提示，不会导致调用方对话流程崩溃。

6. 多 LLM 抽象

LargeLanguageModel 接口统一抽象，内置 DeepSeek、Doubao、Kimi 三种实现，通过 large-language-model.active 配置切换，新增模型只需实现接口。
